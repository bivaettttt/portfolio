01 / Учебная разработка

Задача пользователя

Пользователю нужен личный список доходов и расходов: добавить операцию, просмотреть историю и выбрать валюту отображения. Записи должны быть связаны с конкретным аккаунтом.

Учебное решение разделяет веб-приложение, базу PostgreSQL и небольшой сервис курсов. Курсы заданы константами; подключение к актуальным банковским котировкам не реализовано.

02 / Учебная разработка

Моя роль

Спроектировал связь пользователя с финансовыми операциями, разработал Flask-приложение и отдельный HTTP-сервис курсов. Подготовил SQL-схему, обработчики и формы; при написании кода использовал ИИ по необходимости.

Учебные отчёты оформлены совместно; перечисленные аналитические и технические задачи выполнил самостоятельно.

04 / Учебная разработка

Компоненты и данные

Flask обрабатывает формы и формирует HTML через Jinja2. Для доступа к PostgreSQL используется psycopg2, для вызова сервиса курсов — Requests. Пароли хранятся в виде хешей Werkzeug.

Таблица users хранит аккаунты, operations — дату, сумму, тип и ссылку на владельца. Поле chat_id в этой схеме ссылается на users.id. Внешний ключ задан с ON DELETE CASCADE; тип операции ограничен значениями income и expense.

05 / Учебная разработка

Что есть в коде

Найдены обработчики страниц, HTML-шаблоны, SQL-инициализация и отдельный rate_service.py. Основные маршруты приложения работают с HTML-формами; называть весь проект полноценным REST API было бы неточно.

NUMERIC(12,2) используется в БД, но денежные значения обрабатываются также через float. Для следующей версии нужно согласовать точность вычислений и округление во всех компонентах.

  1. 01Вход → определение пользователя
  2. 02Форма операции → запись в PostgreSQL
  3. 03Запрос курса → отображение в валюте
  4. 04Удаление аккаунта → каскадное удаление операций

06 / Учебная разработка

Проверка результата

Проверены исходный код и скриншоты из отчёта. На них показаны формы и список операций, в том числе отображение в USD.

Отдельный сервис курсов проверен через Flask test client. USD и EUR вернули 200, отсутствующая и неизвестная валюта — 400. Полное приложение с PostgreSQL повторно не запускалось.

07 / Итоги и развитие

Результат, ограничения и развитие

Реализованы исходники учебного веб-прототипа с реляционным хранением и межсервисным HTTP-вызовом. Модель и маршруты доступны для технического разбора.

Что проверить дальше

  • В исходном учебном коде есть небезопасные параметры окружения; целиком он здесь не опубликован.
  • Нужны CSRF-защита, проверка входных данных и безопасная обработка ошибок.
  • Нужны воспроизводимый стенд и фактический протокол проверок авторизации и удаления.
