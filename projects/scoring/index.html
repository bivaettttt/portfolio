01 / Дополнительный учебный проект

Задача и контекст

Учебный проект исследует бинарную классификацию кредитных записей: обучение дерева решений и случайного леса, сравнение показателей и вызов модели через веб-интерфейс.

В репозитории есть данные, скрипт обучения, сохранённая модель, Flask-приложение и графики. Проект не использовался здесь для реальных кредитных решений.

02 / Дополнительный учебный проект

Моя роль и происхождение проверки

Подготовил учебный pipeline обучения и Flask-интерфейс прогнозирования. Использовал ИИ при необходимости генерации кода; это не полностью ручное программирование.

Повторное обучение и проверка семантики good/bad описаны отдельно как проверка портфолио с помощью Codex. Проверка выявила ошибку сопоставления вероятности с классом. Исправление опубликовано в основной ветке.

04 / Дополнительный учебный проект

Данные и обучение

Использованы 1 000 строк и 20 входных признаков. При аудите данные полностью совпали с South German Credit из UCI. Цель kredit кодирует 0 как bad, 1 как good.

Разделение — 80/20, stratify по цели, random_state=42. Сравниваются DecisionTree и RandomForest; лучшая модель выбирается по ROC-AUC. Все колонки числовые, поэтому предусмотренная ветка OneHotEncoder фактически не применяется.

05 / Дополнительный учебный проект

Ошибка смысла прогнозируемого класса

Приложение берёт вероятность класса 1, называет её proba_bad и выдаёт REJECT при превышении порога. Но класс 1 в этих данных означает good — надёжного заёмщика. Таким образом, интерпретация риска и решение интерфейса инвертированы.

Метрики математически воспроизводятся для исходной кодировки, но это не подтверждает корректную оценку дефолта. До исправления семантики API, подсказок и решений приложение следует рассматривать как учебный прототип с выявленным дефектом.

06 / Дополнительный учебный проект

Что удалось воспроизвести

Проверены исходные данные и их кодировка, mapping обучения, порядок классов сохранённой модели, ответ API и отображение результата в браузере. На двух примерах по разные стороны порога интерфейс подтвердил ошибочную трактовку вероятности good как риска.

Числовые метрики и матрица ошибок оставлены во внутреннем протоколе. Здесь они не используются как доказательство качества кредитного решения: исходное приложение ошибочно интерпретирует положительный класс good как риск.

Исходный код исследования и обработчика доступен в GitHub. Результат проверки зафиксирован тестами в репозитории.

07 / Итоги и развитие

Результат, ограничения и развитие

Учебный API запущен на локально переобученной модели. Исправленный API выбирает вероятность класса bad по отображению классов. Проверены значение вероятности, решения по обе стороны порога и ошибки входа. Ссылка ниже ведёт к опубликованному исправлению.

Что проверить дальше

  • Исправить трактовку класса и контракт вероятности, затем проверить решения по обеим сторонам порога.
  • Добавить серверную проверку типов, диапазонов, категорий и порога.
  • Отделить выбор модели от финальной оценки: сейчас сравнение выполняется на том же test.
  • Уточнить подписи признаков, атрибуцию данных и инструкцию запуска. Python 3.12 отдельно не проверялся.
